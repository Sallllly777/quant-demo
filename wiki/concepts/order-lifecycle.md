# 订单生命周期与最终核验

问题：发送返回成功只证明本地请求被接收，不能证明柜台受理、成交或最终空仓。

最小状态链：请求 → 柜台响应 / 委托回报 → 成交回报 → 持仓查询 → 活动委托查询。成交与委托回报可能重复或先后交错；未知状态应保守处理，不能靠一条“已下单”日志宣布通过。

本次验收使用 `(FrontID, SessionID, OrderRef)` 识别本会话订单，成交以交易所/成交编号/交易日去重。总持仓按各行绝对量求和，多 1 与空 1 不相抵；完整查询必须结束且无错误，否则“没有收到记录”不等于零。两轮最终查询进一步检查状态落地，但并不能替代并发账户锁和生产级恢复。

`CloseToday` 与普通平仓不同。当前只允许从空账户买开一手 ag2612，确认今仓，再卖平今；不擅自平外部或跨日仓位。只读行情客户端本来就没有交易连接，因此其空持仓面板不能证明账户已空。

关联：[对象导航](../entities/runtime.md)、[实现取舍](../code/simnow.md)、[来源](../sources/local-records.md)。待验证：故障时真实账户状态和人工恢复；本实验不会承诺异常下必定平仓。
